# 실적 기대 차이 + 투자·위험 전략

`earnings-gap-auto/v1`은 **사용자가 직접 선택한 KOSPI 보통주 후보 티커**의 자체 예상 실적과 시장 컨센서스 차이를 투자·자금·유동성 조건과 함께 평가하는 로컬 연구 도구입니다. 업종은 더 이상 자동차로 고정되지 않으며, 종목/업종 선택은 전적으로 사용자 책임입니다(`config.sector`는 과거 버전과의 호환을 위해 남아 있는 선택 필드일 뿐 어떤 필터에도 쓰이지 않습니다; 실제 집중도 한도는 각 후보의 `forecast.sector` 값으로 계산됩니다). 기존 제품시장 목표가 모델(웹 화면의 기존 티커 분석, KOSPI 보통주 필터)은 이 전략과 완전히 분리되어 그대로 유지되며, 이 문서가 다루는 범위가 아닙니다. 실제 주문을 전송하지 않습니다.

**(과거 기술 — 아래 "자동 연결" 참고) 후보 티커를 고르는 것만으로 전략이 끝나지 않습니다.** 아래 CLI/API는 여전히 사용자가 이 문서가 요구하는 네 분기 실적 전망, 현재/이전 컨센서스, 실적 일정, 자금 계획을 직접(수동으로) 입력하는 경로입니다. 필요한 기간·단위·공개 시각이 맞는 자료를 직접 입력하세요.

## 자동 연결 (웹 화면의 기존 티커 분석)

`POST /v1/analyses`(mode=public, 티커만 입력하는 기존 경로)는 이제 같은 작업에서 이 전략 슬라이스도 **자동으로** 채웁니다. 사용자는 전략 JSON을 직접 작성하지 않습니다.

### 한 분기 실적 추정 (단기, 최장 3개월)

자동 경로는 **한 분기만** 추정합니다. 보유 기간이 길어도 3개월을 넘지 않는 단기 매매 판단용이며, 4개 분기나 연간 전망을 만들지 않습니다. 4개 분기 전망·컨센서스는 아래 수동 CLI/API(`/v1/strategy/*`)에만 남아 있습니다.

- **추정 대상 분기**는 둘 중 하나입니다: 방금 끝났지만 실적이 아직 공시되지 않은 직전 분기, 또는 진행 중인 분기(`singleQuarterHorizon`, `src/strategy/time.ts`). 직전 분기 실적이 이미 제공 문서에 있으면 진행 중인 분기를 추정합니다. 그 밖의 분기나 여러 분기를 담은 전망은 `FORECAST_HORIZON_NOT_SINGLE_QUARTER`로 버립니다.
- **추정 근거는 최근에 공시된 한 분기 실적만 있어도 됩니다.** 여러 분기 시계열이나 컨센서스가 없다는 이유로 추정을 포기하지 않습니다. 최근 분기 실적에 문서에 나온 변화 요인(가이던스, 수주·판가·물량·환율·원가, 계절성)을 반영하고, 근거가 없으면 최근 분기 수준 유지를 명시적 가정으로 둡니다.
- 결과 상태(`strategyAuto.status`): 검증된 추정이 있으면 컨센서스가 없어도 `estimate_only`(추정 완료)입니다. 같은 분기의 현재/이전 컨센서스와 촉매까지 문서 인용으로 확보되면 `eligible`/`ineligible` 판정까지 합니다. 추정 자체를 만들지 못했을 때만 `insufficient_data`입니다.
- `bridge.ntmEpsKRW`는 필드 이름만 그대로이고 값은 **그 한 분기의 EPS**입니다. 4를 곱하거나 연환산하지 않습니다.
- 촉매(실적발표 등)는 판단 시점으로부터 92일 이내여야 합니다.

### 참고: 네이버 분기 컨센서스

네이버 증권의 `/api/stock/{ticker}/finance/quarter`에서 `isConsensus: "Y"`인 분기 열을 수집해 `strategyAuto.quarterlyConsensus`로 추정 옆에 표시합니다. 추정을 대신하지 않는 참고값이며, 없어도 추정은 그대로 나옵니다. 금액은 네이버 화면 단위인 억원에서 원으로 환산하고 EPS는 원/주 그대로 유지합니다. 결측치는 0으로 채우지 않습니다.

자체 추정과 **동일한 분기**이면 매출·영업이익의 차이를 표시합니다. 공급자 응답에는 연결/별도와 희석주식 기준이 명시되지 않으므로 EPS 차이는 계산하지 않으며, 매출·영업이익 차이도 적합 판정에 사용하지 않습니다. 다른 분기만 있으면 컨센서스 자체만 표시합니다.

조회 시각(`observedAt`)은 증권사 보고서 발행·수정 시각이 아닙니다. 현재 스냅샷을 과거 `asOf`에 소급 적용하지 않으며, 이전 값/수정률을 만들지 않습니다. 공개 엔드포인트에 값이 없거나 응답 형식이 바뀌면 부분 결과로 남습니다.

### 다음 분기 적정 주가 (PER 유지)

`strategyAuto.nextQuarterPrice`는 추정 분기 T의 참고 가격입니다(`src/strategy/price-target.ts`). 적합 판정에는 쓰지 않습니다.

```text
기준 분기 B = T의 직전 분기
PER       = B의 일별 종가 평균 ÷ (B-3 … B 실제 EPS 합)
적정 주가 = PER × (B-2 … B 실제 EPS + T 추정 EPS)
```

- 직전 분기에 시장이 실제로 매긴 PER을 유지하고, 예측 분기를 포함한 최근 4분기 EPS 변화만 가격에 반영합니다. B 평균 종가 대비, 최근 종가 대비 변화율을 함께 표시합니다.
- 일별 종가는 네이버 `/price`, 실제 분기 EPS는 네이버 분기 실적 표(`isConsensus=N`)입니다. T의 EPS는 자체 한 분기 추정(`bridge`)입니다. 네이버 EPS의 기본/희석 기준이 표시되지 않아 기준 차이가 있을 수 있습니다.
- 빠진 값을 채우지 않습니다: 추정 EPS 없음(`NO_FORECAST`), B의 종가가 분기를 덮지 않음(40거래일 미만 또는 분기 경계에서 10일 넘게 떨어짐, `BASE_PRICES_INCOMPLETE`), 실제 EPS 누락(`ACTUAL_EPS_MISSING`), 4분기 EPS 합이 0 이하(`NON_POSITIVE_BASE_EPS`/`NON_POSITIVE_TARGET_EPS`)이면 `unavailable`과 사유를 냅니다.
- 네이버 표와 일별 시세는 현재 스냅샷이므로 과거 기준일 분석에서는 계산하지 않습니다.

### 계산 방식

- 기존 공개 수집(DART 재무제표/공시, Naver 시세·뉴스)을 재사용하고 별도 전략 호출로 한 분기 실적 추정(부문별 판매량/단가/변동비/고정비, 자금계획), 그 분기의 현재/이전 컨센서스, 예정된 촉매(실적발표 등)를 추출합니다.
- **자금 계획 자동 보완**: 현금·차입 등 재무 근거와 검증된 실적 전망이 있는데 자금 계획이 누락되거나 검증에서 탈락하면, 전략을 추출한 모델에 자금 계획만 한 번 추가 요청합니다. 연결 재무제표·현금흐름표·주석을 바탕으로 CAPEX, 운전자본, 차입 상환 등을 명시적 가정으로 전망합니다. 모델 전달 자료에서는 현금·차입·CAPEX·감가상각·세금·이자 행을 우선 보존합니다. 누적 현금흐름의 기간 환산과 첫 전망 분기 시작 잔액의 추정 근거를 요구하며, 자료 누락을 0으로 채우지 않습니다. 출처·분기·상환 잔액 검증을 통과해야 위험 계산에 사용합니다. 보완 실패는 실적 전망을 없애지 않고 구체적 부족 항목/실패 사유를 표시합니다.
- 각 항목은 `src/intelligence/strategyVerify.ts`가 **결정론적으로만** 검증합니다: 실제 공급된 문서를 인용한 근거(`source`)가 없는 컨센서스·촉매·유동성 수치는 절대 채택되지 않고 명시적으로 "미확보"로 남습니다(추측/모델 지식으로 채우지 않음). 추정 분기의 부문 수치는 근거 문서를 인용한 `assumptions`(명시적 가정)로 채택될 수 있습니다.
- **연간 컨센서스 EPS나 다른 분기의 값을 추정 분기의 컨센서스로 쓰지 않습니다.** 정확히 같은 한 분기를 대상으로 하고 공개 출처가 확인되는 컨센서스가 없으면 `currentConsensus`/`priorConsensus`는 `null`로 남고 그 이유가 `strategyAuto.missing`에 기록됩니다.
- 전략 추출과 자금 계획 보완은 제품시장 Dataset과 **별도 호출**이며, 두 번째 모델의 별도 감사 대상이 **아닙니다**(결정론적 인용/출처 검사만 적용). Dataset 쪽의 이중 모델 교차검증보다 약한 보증이며, 이 문서와 결과의 `notes`에 한계로 남습니다. 미래 자금 계획은 공시의 실제 확정 계획과 동일하다는 보장이 없는 모델 추정치입니다.
- 결과는 `strategyAuto`로 노출됩니다: 한 분기 실적 브릿지(`bridge`)와 자금 계획이 있으면 위험(`risk`), 네 자료(예측/현재컨센서스/이전컨센서스/촉매)가 모두 확보·정합하면 전체 적합성 평가(`evaluation`, 기존 `screen()`과 동일한 로직)까지 채웁니다. 컨센서스/촉매가 없어도 실적 브릿지·자금 위험은 계속 보이며 기존 밸류에이션(제품시장 목표가)을 가리지 않습니다.
- **비중/투자금액을 계산하지 않습니다.** 수수료·슬리피지·세금·초기자본은 개인 포트폴리오 가정이라 자동으로 지어내지 않으며, 실제 배분이 필요하면 여전히 `POST /v1/strategy/screen`을 명시적 설정으로 호출하세요. 자금 위험의 최소 현금 버퍼만 서버 설정 `STRATEGY_MIN_CASH_BUFFER_KRW`(선택, KRW)로 지정할 수 있고, 지정하지 않으면 0(현금이 실제로 음수가 될 때만 부족으로 표시)을 사용한다고 결과에 명시합니다.
- 자동 추출 결과는 저널(`/v1/strategy/records/*`)에 저장되지 않는 일회성 계산입니다. 반복 재현하려면 여전히 수동 기록 API를 쓰세요.
- 웹 화면(`public/app.js`)은 이 결과를 "실적 전망·투자 위험" 섹션으로 표시합니다. 자금 계획이 확보되면 기본/하방 시나리오와 분기별 투자·운전자본·차입 상환·기말 현금·추가 자금 필요액을 보여줍니다. 적용하려면 서버를 재시작하고 새 분석을 실행하세요. 기존 완료 작업의 결과는 갱신하지 않습니다.

## 실행

```sh
# 후보 선정 + 기업 투자/자금 위험 + 포트폴리오 비중
npm run strategy -- screen examples/strategy/screen-request.json

# 선정 결과를 다음 제공 거래일 시가부터 고정 20거래일 동안 재생
npm run strategy -- replay examples/strategy/screen-request.json examples/strategy/replay-input.json

# EPS가 높아도 CAPEX 부담으로 현금 부족 → 매수 제외
npm run strategy -- screen examples/strategy/screen-request-funding-gap.json

# 거래대금 제약 → 1위 후보 비중을 20%에서 5%로 축소
npm run strategy -- replay examples/strategy/screen-request-liquidity-limit.json examples/strategy/replay-input.json

# 전액 현금 유지 사례
npm run strategy -- replay examples/strategy/screen-request-no-trade.json examples/strategy/replay-input.json
```

**예제의 회사·예측·가격·위험 시나리오는 모두 합성 데이터입니다. 예제 수익률은 실제 투자 성과가 아닙니다.**

## 선별 규칙

1. 사용자가 선택한 KOSPI 보통주이며 보통주 이름/티커 필터를 통과해야 합니다(업종은 사용자 선택이며 자동차로 제한되지 않습니다). 거래소 분류를 독립적으로 인증하는 기능은 아닙니다.
2. KST 의사결정 분기의 **바로 다음 분기부터 네 개의 완전한 분기**를 예측합니다. 네 분기 EPS를 합산하며 한 분기 EPS에 4를 곱하지 않습니다. 출력의 기존 `ntmEpsKRW` 이름은 호환성을 유지한 것이며 정확한 당일부터 12개월 전망을 뜻하지 않습니다.
3. 현재/이전 컨센서스가 같은 티커·네 분기·연결·보통주 희석 EPS·원/주 기준이어야 합니다. 기본 실험값은 EPS 차이 ≥10%, 컨센서스 수정률 >0%, 현재 컨센서스 30일 이내, 이전 컨센서스는 현재보다 20~40일 전, 공개 일정상 촉매는 1~60일 후입니다.
4. 기업 투자/현금 계획과 과거 거래대금 자료가 기본적으로 필수입니다. 빠지면 `RISK_DATA_MISSING` 또는 `LIQUIDITY_DATA_MISSING`으로 제외하며 0으로 추정하지 않습니다.
5. 기본 현금흐름에 추가 조달 필요액이 있으면 제외합니다. 기본 설정에서는 하방 시나리오 자금 부족도 제외하며, 기본 EBIT/현금이자 배율이 1 미만인 분기도 제외합니다. 현금이자가 없는 경우 배율은 `null/NO_CASH_INTEREST`로 표시하고 이 조건만으로 탈락시키지 않습니다.
6. 남은 종목은 EPS 차이 내림차순·티커 오름차순으로 순위를 정합니다. 동일 티커를 두 번 제출하면 거부합니다. 여러 예측 버전 중 사용할 기록은 명시해야 하며 과거 결과에 맞춰 고른 기록은 소급 연구입니다.

위 수치들은 검증할 첫 실험의 설정값이며 학습된 최적 임계값이나 수익 보장 조건이 아닙니다. 설정 변경 시 전체 설정 해시가 바뀝니다.

## 기업 이익과 투자 현금흐름

부문별 `판매량 × 판매가격`, `판매량 × (판매가격 − 단위원가) − 고정비`를 합산해 분기 매출·영업이익을 계산합니다. 순이자·발생세금·비지배·우선주 배분·희석주식수로 보통주 EPS를 구합니다. 부문별 및 이익 연결 가정에는 근거 시각과 가정 설명이 필요합니다. 회사 전체를 설명한다는 선언은 사용자 책임의 미검증 입력으로 표시합니다.

투자/현금 계획은 다음 계산을 따릅니다.

```text
영업현금 대용값 = 영업이익 + 감가상각 − 현금세금 − 현금이자
                 + 기타 영업현금 조정 − 운전자본 증가
투자 후 잉여현금 = 영업현금 대용값 − 설비투자
기말 현금 = 기초 현금 + 투자 후 잉여현금 − 원금상환
            + 확약 신규차입 − 배당·자사주 매입
기말 차입금 = 기초 차입금 − 원금상환 + 확약 신규차입
```

- 감가상각은 영업비용에 이미 포함된 것으로 가정하고 현금흐름에서 한 번만 더합니다.
- 설비투자와 차입금 원금은 EPS에서 다시 차감하지 않습니다. 신규차입은 이익이 아닙니다.
- 운전자본 증가가 양수면 현금 유출, 음수면 회수입니다. 현금세금과 발생세금은 지급 시점이 달라 별도 입력입니다.
- 현금이 음수가 되어도 가상의 추가 차입을 넣지 않습니다. 입력한 최소 현금 버퍼를 지키기 위한 **최대 추가 조달 필요액**을 표시합니다.
- 잉여현금이 음수라도 기존 현금/확약 차입으로 버틸 수 있으면 이 이유만으로 제외하지 않습니다.
- 기초 잔액은 첫 전망 분기 시작 시점의 **추정 가용 현금·차입금**입니다. 오늘의 실제 잔액을 그대로 쓰는 의미가 아닙니다. 현재부터 그 시점 사이의 자금 흐름과 분기 중 최저 현금은 별도 위험입니다. 이 모델은 분기 경계만 평가하며 실제 현금흐름표/지급불능 판정을 대체하지 않습니다.

`evaluations[].risk`에서 기본/하방 각각의 분기 현금흐름, CAPEX/매출, 이자보상, 순차입금, 최소 분기 경계 현금, 추가 조달 필요액을 확인할 수 있습니다. 탈락 종목에도 계산 결과가 남습니다.

## 하방 시나리오

초기 설정은 판매량 −10%, 판매가격 −5%, 단위원가 +5%, 연 현금이자 +200bp입니다. 판매량 감소에 따라 총 변동비도 줄고, 금리 충격은 해당 분기 기초 차입금에 1/4년을 적용합니다. 추가 이자를 이익과 현금 양쪽에 한 번씩 반영합니다.

고정비·CAPEX·운전자본 계획·현금세금·원금상환·확약차입·배당은 고정합니다. 세금 환급을 즉시 가정하지 않습니다. 모든 차입금이 즉시 재가격되는 시나리오이므로 고정금리·헤지는 구분하지 않습니다. **확률·VaR·신뢰구간이 아닙니다.**

관측 시각이 있는 주가와 명시적 기준 PER가 있으면 PER 고정 시 하방 가치/손실도 계산합니다. EPS가 음수인 스트레스에서는 가치의 하한을 0으로 둔 시나리오일 뿐, 주가가 실제로 0이 된다는 예측이 아닙니다. 일부 종목의 진단 입력이 없으면 전체 포트폴리오 스트레스 손실은 `null`이며 계산된 투자 비중만 표시합니다.

## 투자금액과 유동성

기본 최대 5종목, 종목당 최대 20%, **동일 업종(사용자가 선언한 `forecast.sector` 라벨) 전체 최대 60%**입니다. 이 60% 한도는 업종마다 독립적으로 적용됩니다: 후보가 여러 업종에 걸쳐 있으면 업종별로 각각 60%까지 허용되므로 포트폴리오 전체 투자 비중은 100%까지 갈 수 있습니다(동일 업종에 몰리면 그 업종만 60%로 묶입니다). 각 종목의 초기 한도는 `min(종목 상한, 1/선정 종목 수, 같은 업종 상한 / 같은 업종 선정 종목 수)`입니다. 추가로 `과거 평균 일거래대금 × 참여율(기본 1%)`까지 투자합니다. 업종 한도든 유동성 한도든 줄인 자금은 다른 종목에 재배분하지 않고 현금으로 남깁니다. 차입/레버리지는 없습니다. 업종 라벨은 거래소가 검증한 분류가 아니라 사용자가 입력한 문자열이므로, 같은 업종을 가리키려면 후보마다 동일한 표기를 써야 합니다.

과거 거래대금은 예측 작성 전에 관측·공개됐고 결정 시점에 기본 10일 이내여야 합니다. 거래대금 한도는 체결 가능 금액의 근사치이며 체결 보장이 아닙니다. 비용까지 포함한 매수 예산을 한도와 비교하므로 조금 더 보수적으로 배분됩니다. `portfolio.positions[].liquidityLimited`는 그 종목의 실제 비중이 업종 한도가 아니라 유동성 한도 때문에 줄었는지를 구분해 보여줍니다.

`portfolio`에는 실제 투자금액·현금·업종별 비중(`sectorWeights`)·가장 큰 업종 비중(`largestSectorWeight`)·최대 종목 비중·거래 참여율·유동성 제한 여부·스트레스 가치 계산 범위가 나옵니다. 여러 업종을 섞어 담을 수 있지만 업종 간 최적 분산을 계산하는 기능은 아닙니다. 환율·관세·신용스프레드·약정 위반·차환 실패·체결 공백·유동성 동결·모델 오차 등 미계산 위험은 `unmodelledRisks`로 구분합니다.

**업종 기준지수(`sectorBenchmark`) 한계:** 재생(replay) 입력에는 업종 기준지수를 하나만 넣습니다. 선정된 종목이 여러 업종에 걸쳐 있어도 이 기준지수가 자동으로 그 업종 조합에 맞춰 선택되거나 가중되지 않습니다. `sectorReturnPct`/`excessReturnVsSectorPct`/`cashWeightedSectorReturnPct`는 사용자가 넣은 그 하나의 지수와의 비교일 뿐이며, 결과의 `notes`에도 이 한계가 명시됩니다.

## 시점과 성과 재생

- 모든 출처 시각을 확인합니다. 컨센서스 봉투의 `knownAt`만 과거로 적어도 원문 시각이 더 늦으면 탈락합니다.
- `forward` 입력은 서버가 기록한 네 가지 자료(예측/현재 컨센서스/이전 컨센서스/일정) 모두 결정 시점 이전에 존재해야 합니다. 이력 가져오기·합성 자료가 섞이면 더 약한 자료 유형이 적용됩니다. 일반 입력으로 forward를 선언할 수 없습니다.
- 현재 API는 사전에 전략 결정을 등록하는 기능이 아닙니다. 저장된 입력을 재선정하므로 **실제 forward 운용 성과라고 표시하지 않습니다**. 합성 자료가 포함되면 `synthetic`, 그 외는 `retrospective_research`입니다.
- 사용자가 제공한 공통 거래일 목록의 첫 시가에 진입하고 지정한 거래일 수의 마지막 종가에 청산합니다. 결정은 첫 시가보다 이전이어야 합니다. 거래일 목록의 완전성/거래소 일치 여부는 독립적으로 검증하지 않으므로 빠진 휴장·거래일을 포함해 원자료가 정확해야 합니다.
- 가격은 총수익 조정 기준이며 소수 단위 정규화 모의 운용입니다. 배당을 다시 더하지 않습니다. 실제 정수 주식 주문 체결 재현은 아닙니다.
- 수수료·슬리피지·매도세는 명시적 입력이며 예제 세율은 현재 법정세율이라는 주장이 아닙니다. `risk.minimumCashBufferKRW`와 초기자본도 직접 입력합니다.
- 종목/기준지수 가격이 누락되면 `incomplete`이며 수익률을 만들거나 다른 종목으로 바꾸지 않습니다. 실데이터는 보유 기간이 끝나고 해당 가격이 평가 시각까지 알려졌어야 합니다.
- 총수익·비용 차감 수익·보유 중 최대낙폭·회전율·KOSPI/업종 대비 초과수익을 계산합니다. 동일 현금 비중의 업종 기준수익도 별도 제공합니다. 비용을 제외한 기준지수 수익과 비용 포함 전략 수익의 비교입니다.
- 같은 네 분기의 실제 EPS가 제공되면 예측 오차도 계산합니다. 0에 가까운 실제 EPS는 오차 금액만 제공하고 비율은 `null`입니다.
- 단일 20거래일 코호트이며 반복 포트폴리오 최적화/연환산 Sharpe/CAGR는 제공하지 않습니다. 각 결과에 전체 입력·출처·설정·해시가 남습니다.

`gapPct`, `revisionPct`, 비중, 참여율은 소수 비율(0.1 = 10%)입니다. 재생 결과 `netReturnPct`, `maxDrawdownPct`, `excessReturnVs…Pct`는 퍼센트 수치입니다. 초과수익은 퍼센트포인트 차이입니다.

## 기록 및 API

CLI와 API는 `DATA_DIR/strategy/{forecasts,consensus,catalysts}`(기본 `data/records/strategy/…`)의 같은 파일을 사용합니다. ID와 기록 시각은 서버가 부여하며 수정 기록은 새 파일입니다. 예:

```sh
npm run strategy -- record-forecast my-forecast.json --mode=forward
npm run strategy -- record-consensus my-consensus.json --mode=forward
npm run strategy -- record-catalyst my-calendar.json --mode=forward
npm run strategy -- list forecasts
npm run strategy -- get forecasts <id>
```

과거 원본은 `--mode=historical_import_unverified --archive-source=archive-source.json`, 가상 자료는 이에 `--synthetic`을 추가합니다. 원본 자료를 확보하지 않은 채 오늘 LLM 지식으로 과거 예측을 만들어서는 안 됩니다. 가져온 자료는 독립 검증된 과거 정보가 아닙니다.

선별 JSON은 예제처럼 각 자료를 직접 넣거나 `forecast: {"recordId":"…"}`처럼 네 자료를 각각 참조합니다. `diagnostic`은 선택 항목입니다. 모든 신규 설정은 `examples/strategy/config.json`을 참고하세요. 이전 전략 입력에 기업/범위/근거가 누락돼 있으면 저장 자료를 덮어쓰지 말고 새 버전으로 보완합니다.

| 메서드 | 경로 | 내용 |
|---|---|---|
| GET | `/v1/strategy/config/defaults` | 실험 기본값; 비용/자본/현금 버퍼는 별도 입력 |
| POST/GET | `/v1/strategy/records/forecasts` | 예측 저장/목록 |
| POST/GET | `/v1/strategy/records/consensus` | 컨센서스 저장/목록 |
| POST/GET | `/v1/strategy/records/catalysts` | 일정 저장/목록 |
| GET | `/v1/strategy/records/{kind}/:id` | 원본 조회 |
| POST | `/v1/strategy/screen` | `{config, decisionAt, candidates}` |
| POST | `/v1/strategy/replay` | `{screen: <선별 요청>, replay: <가격/거래일>}` |

기본값 조회 외에는 기존 API_KEY 설정 시 `x-api-key`가 필요합니다. (과거 기술: 이 표의 경로는 여전히 유효한 **수동** 입력/재현 경로입니다. 웹 화면의 자동 연결은 위 "자동 연결" 절과 `POST /v1/analyses`를 참고하세요.)

## 실제 성과 검증에 남은 데이터 작업

기간이 명확한 과거 컨센서스, 당시 작성된 판매량/가격/비용·투자·차입 계획, 당시 종목군(상장폐지 포함), 가격·지수의 같은 조정 기준을 확보해야 합니다. 현재 Naver `cnsEps`만으로 네 분기 컨센서스를 대체하지 않습니다. 전략을 반복 평가하려면 실패한 실험을 포함한 실행 기록과 사전에 고정한 평가 구간도 필요합니다. 구현 테스트는 계산을 검증하며 투자 수익성을 증명하지 않습니다.
