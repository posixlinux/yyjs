## Objective and scope
Build a usable local research/paper-trading vertical slice, not brokerage execution. Test whether an independently constructed next-four-quarter common EPS forecast, above same-period consensus with positive revisions, identifies subsequent net excess returns. Start with a declared automotive universe. No claims that the hypothesis works before out-of-sample results exist. Preserve existing research/model API behavior; this strategy has a separate version and inputs. Do not spend this task fixing unrelated exceptions.

## Fixed experiment configuration
Version `earnings-gap-auto/v1`; sector automotive; KRW; KOSPI common shares. Config is supplied/frozen with each run and has a digest in output; do not tune thresholds on the evaluated sample. Proposed explicit defaults are hypothesis parameters, not learned values: gap >= 10%, positive same-horizon consensus revision (>0), current consensus <=30 calendar days old, prior consensus 20–40 calendar days before current, catalyst 1–60 calendar days ahead, max 5 holdings, max 20% initial capital per holding, hold 20 sessions. Use a ONE-COHORT replay in v1: screen at a supplied decision close, enter next session open, hold fixed 20 sessions, exit final held session close. No overlapping cohorts, no reinvestment, no averaging trade returns and calling it a portfolio. Fewer eligible names => unused capital stays cash. Rank by EPS gap descending, tie ticker ascending. All-in long positions only, no leverage, cash earns zero. Strategy filters and limits may be explicit config but results must show them. Extend to rolling cohorts later, do not mislabel a single cohort as a full walk-forward optimizer.

## Earnings model (four quarters, not quarter EPS multiplied by four)
Each snapshot describes one ticker, sector, fiscal scope, currency, and EXACT four consecutive future fiscal quarters (canonical YYYYQn). Assume calendar fiscal year only for v1, explicitly restrict. All forecast quarters must end after decision time. Each quarter contains complete declared company coverage via named segments, each with volume, unitPriceKRW, variableCostPerUnitKRW, fixedCostKRW; company total revenue=sum(volume*price), operating profit=sum(volume*(price-variableCost)-fixedCost). No fabricated missing segments: require explicit coverage attestation and label it user-supplied, not independently verified. Revenue positive, costs nonnegative, volume nonnegative; losses allowed. For each quarter explicitly supply netInterestKRW, taxRate, noncontrollingShare, preferredClaimsKRW and dilutedCommonShares. tax=max(pretax,0)*rate; commonEarnings=(pretax-tax)*(1-noncontrollingShare)-preferredClaims. Sum quarterly common EPS to NTM EPS. Show segment/quarter bridge and break-even/sensitivity: price +1% holding all else fixed, volume +1% with variable costs scaling, variable cost +1%, plus corresponding EPS changes. These are deterministic perturbations, not confidence intervals.
Inputs/assumptions must have provenance and known-at timestamps; LLM model_knowledge must not be eligible for strategy decisions. Analyst-supplied assumptions must be explicitly labeled as assumptions. Do NOT auto-convert existing single-quarter model output into a strategy forecast.

## Expectations and catalyst
Current AND prior consensus snapshots must be positive common diluted EPS, consolidated, KRW/share, same ticker and EXACT four quarter horizon as forecast. Cannot compare annual consensus to quarterly EPS, differing fiscal periods, trailing EPS, negative/near-zero denominator, or a rolling horizon that changed. Require unit/scope/horizon metadata and sources. Gap=(forecastNTMEPS/currentConsensusEPS-1); revision=(current/prior-1). Use a documented minimum positive EPS config to avoid division by near zero. Missing inputs -> explicit ineligible decision with reasons (schema errors may reject malformed inputs). catalyst schedule needs an observed source with knownAt <= decision; event time strictly after decision; do not use actual future announcement surprises.
Fixed-PER diagnostic: optional explicitly sourced referencePE and current price allow NTM forecast value, current-price implied EPS=currentPrice/referencePE, earnings-only upside. No automatic PER expansion, no fabricated expected return/probabilities. Diagnostic price is not the trade signal.

## Time integrity and persistence
Timestamp all knowledge/provenance with ISO datetimes and offsets; compare epoch times, not timestamp strings. Period end is not publication time. Every relevant source/assumption/consensus/schedule must have knownAt <= forecast/decision where appropriate. generatedAt <= decisionAt; knowledge used to produce forecast must be known at generation; current comparison consensus may arrive later but <= decision. Forecast observation cutoff must be explicit. Record modes:
1. Forward snapshots: server assigns immutable recordedAt from its clock, IDs/hash generated server-side. Eligible only for decisions at or after recordedAt. Client cannot backdate recordedAt. Store full input, computed forecast and strategy version with exclusive atomic create; reject overwrite; append new records for revisions. Do not overwrite old predictions. Concurrent writes safe. Listing/restart reads supported.
2. Historical imported records: explicitly labeled `historical_import_unverified`, require archive provenance and original forecast generatedAt; record actual import time separately. They can be replayed for research but cannot be labeled observed forward performance. Imported historical forecasts may not be generated from today's LLM memory. Source attestation is not independent verification. Every result says whether evidence is forward, historical-unverified, or synthetic. Synthetic example/test can use historical mode plus synthetic:true.
Automatic consumption of existing Naver cnsEps is NOT allowed until exact horizon and basis are known. Document this concrete integration gap. Expose screening/replay from saved IDs so the journal is actually used.

## Replay accounting and measurements
Input explicit chronological exchange sessions with openAt/closeAt and coherent open/close TOTAL-RETURN-ADJUSTED prices for selected tickers, market benchmark and sector benchmark. Require a declared consistent adjustment basis, provider/source, and positive prices. If using total-return-adjusted fractional units, label as normalized portfolio simulation; dividends already included, DO NOT add dividends again; execution impact is a cost approximation. Missing selected ticker/benchmark sessions makes performance incomplete/unavailable, never silently drops a loser or forward-fills stale prices. Duplicate ticker sessions or bad chronology rejected. One common calendar required. Source describes known-at historical prices as outcomes only; future outcomes must never affect screening. Eligibility/ranking must not depend on available price outcomes; missing outcomes MUST NOT replace a selected ticker with a runner-up.
Decision is before next session open (strict); no same-close fills. Hold N sessions including entry session; marks at every held close; exit last close. FeeBps, slippageBps EACH SIDE and sellTaxBps explicitly required in run config (do not hardcode current legal tax rates); user chooses assumed values. Entry effective cost=open*(1+slippage)*(1+fee); buy fractional units within per-position budget; exit proceeds=close*(1-slippage)*(1-fee-sellTax). Check fractions valid. Idle cash remains. Final equity includes exit costs. Equity curve begins with pre-entry capital so costs count in max drawdown. Report gross vs net, turnover/cost breakdown, portfolio return, market and sector returns over SAME entry-open/exit-close horizon, excess return in percentage points, max daily drawdown; selected/excluded reasons, dates and no-trade cash cases. Benchmark returns are normalized total returns, no strategy trading costs; label comparison. No annualized Sharpe/CAGR from one short cohort; no probabilities from bear/base/bull. Incomplete outcome dataset -> no fabricated numeric performance. Report forecast accuracy only when matching realized EPS is explicitly supplied; optional for v1, do not invent.

- Equivalent timezone timestamps compare correctly; archive import after decision does not masquerade as forward; forward timestamp can't be supplied/backdated.

- Immutable files across restarts, same ID can't overwrite; authenticated routes and CLI example complete.
